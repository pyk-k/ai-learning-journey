## 【今日目标】

把诊断报告点名的**前三个薄弱点**从"会用"变成"用稳"：

| # | 诊断报告原文 | 今天要达成的状态 |
|---|---|---|
| 1 | **字符串和数字类型容易混淆** —— `"80" + 10` 会报错 | 看到 `input()` / `split()` / `json` 的数据，能立刻意识到"这是 str"；要算数先转换 |
| 2 | **`print` 和 `return` 的职责容易混淆** | 明确一条铁律：**算结果的函数不 print，只 return**；打印是调用方的事 |
| 3 | **异常捕获范围曾经过大** —— `except Exception:` 容易掩盖真正的错误 | 能写出精准的 `except`，并知道**哪些错误不该被 try 包住** |

这三个不是三个独立知识点，是一条链：

```
数据是 str（类型）
   │  → 不转换就运算 → 崩
   ▼
函数拿到数据 → 算完该 return 还是 print？（返回值）
   │  → 混了就直接 print 掉、调用方拿不到结果
   ▼
算的时候可能出错 → 用多大范围的 except 兜？（异常边界）
   │  → 兜太大 → 真正的 bug 被吞掉，你永远发现不了
```

**今天的核心认知**：`try` 的作用不是"让程序不崩"，而是"**让程序只在预期的地方不崩**"。
兜得越宽，你越看不见真相。

### 任务 1（50 分钟）· 类型转换与失败路径

新建 `day1/types_drill.py`，写一个函数：

```python
def parse_score(text):
    """把字符串成绩转成 float，非法输入抛 ValueError"""
```

要求：

- `parse_score("80")` → `80.0`
- `parse_score(" 95.5 ")` → `95.5`（**能处理前后的空格**）

然后在同文件写 `main()`：

- 用 `input()` 收一个成绩

- 成功则打印转换后的值，并且**打印它的类型**（`type()`）

**通关标准**：手动输入 `abc`、空串、`80`、` 95.5 ` 四种情况，程序都不崩、输出符合预期。

### 任务 2（50 分钟）· print 与 return 的职责分界

> 这个任务直接来自诊断报告原话：
> `print`：把内容显示给用户；`return`：把结果交给调用者继续使用。

新建 `day1/summarize.py`，**写三个函数，其中两个绝对不许出现 `print`**：

```python
def parse_scores(text):
    """输入 "80,95.5,60"，返回 [80.0, 95.5, 60.0]；
       空字符串或全是空白 返回 []；
       含非法项 抛 ValueError"""

def build_summary(scores):
    """输入 [80.0, 95.5, 60.0]，返回
       {"count": 3, "average": 78.5, "max": 95.5, "min": 60.0}；
       输入 [] 返回 {"count": 0, "average": None, "max": None, "min": None}"""

def show_summary(summary):
    """把一个 summary 字典漂亮地打印出来"""
```

然后 `main()`：`input()` → `parse_scores` → `build_summary` → `show_summary`。

**硬性要求**：

- `parse_scores` 和 `build_summary` 里**一个 `print` 都不许有**。违规就是没完成。
- `build_summary` 收到空列表**不许崩**，返回上面那个全 `None` 的字典。
  （这正是你摸底题 7 首答 5 分的那个坑——空输入没处理。）
- `show_summary` 是唯一有权限 print 的函数。

**通关标准**：输入 `80,95.5,60` 得到正确的四个值；输入空串得到 `count: 0` 且不崩；
并且在注释里写一行：**为什么 `build_summary` 不直接 print？**

### 任务 3（50 分钟）· 异常边界

这一题不给完整答案。给你一个**有问题的**函数，你先运行它，再回答我。

新建 `day1/error_boundary.py`，原样抄进去：

```python
def average(scores):
    """返回平均分"""
    try:
        total = 0
        for score in scores:
            total = total + score
        return total / len(scores)
    except:
        print("出错了")
        return None
```

**要做三件事：**

**① 先运行，找出它藏了几个问题**

在同一个文件里依次调用，每调用完贴一次输出：

```python
average([80, 90, 70])       # 正常
average([])                 # 空列表
average(["80", 90])         # 混了字符串
average(None)               # 传了 None
```

**② 回答：** 上面四个调用里，哪几个本该报错、却被这个 `except:` 藏起来了？
（提示：`[]` 和 `None` 的错误**性质完全不同**——一个是"没有元素"，一个是"根本不是列表"。它们该被同样对待吗？）

**③ 重写它**，要求：

- 只捕获你**真正预期**的异常，写清楚是哪个异常类
- `scores` 为空 → **不要让异常发生**，用 `if not scores:` 提前返回 `None`
  （这就是诊断报告里说的"或先用条件判断处理正常边界情况"）
- 函数里**不许有 `print`**，出错时 `return None` 或抛出
- 重写后**把上面四个调用再跑一遍**，输出和第一遍对比

**通关标准**：能说清"为什么 `[]` 不该用异常处理，而 `"80"` 可以"。

## 【今天就这一件事】

如果今天只记住一句话：

> **`try/except` 不是用来"让程序不报错"的，是用来"让程序只在预期的地方不报错"的。**

诊断报告说你"异常捕获范围曾经过大"，本质是你把 `try` 当成了护身符——
**看到可能出错就包一层，包完自己也说不清里面到底可能出什么错。**

今天过后，你应该能对着任何一个 `try`，说清楚三件事：

1. 我在防哪个异常？
2. 这个异常为什么**预期内**？
3. 出了别的异常，我**希望它崩**吗？
